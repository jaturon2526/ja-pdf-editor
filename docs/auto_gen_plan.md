# แผนการพัฒนาฟีเจอร์ "สร้างเอกสารอัตโนมัติ (Auto-Gen)"
**ชื่อเดิมที่คุ้นเคย:** Mail Merge
**จุดประสงค์:** สร้างเอกสาร Word และ PDF จำนวนมากอัตโนมัติ จากไฟล์ Template (.docx) และ Data (.json / .csv)

## 🛠 เทคโนโลยีหลัก
- **Python Library:** `docxtpl` (python-docx-template)
- **Engine แปลง PDF:** LibreOffice (รันผ่าน subprocess แบบ headless)
- **Input:** 1x Template (.docx), 1x Data (.json/.csv)
- **Output:** ไฟล์ `.zip` ที่บรรจุไฟล์เอกสารย่อยๆ (1 รายการ = 1 ไฟล์)

## 💡 โครงสร้างข้อมูล (Data Structure)
ระบบรองรับ **Nested Arrays (Array ย่อย)** สำหรับสร้างตารางแบบไดนามิกได้ เช่น บิล 1 ใบ มีรายการสินค้าหลายรายการ:
- ใช้คำสั่ง `{%tr for item in array_name %}` และ `{%tr endfor %}` โดย**ต้องวางแยกไว้คนละบรรทัด (คนละ Row) กับแถวข้อมูล** เพื่อให้ระบบงอกบรรทัดตรงกลางให้ (ห้ามใส่ tag เปิด/ปิดไว้ในบรรทัดเดียวกัน)
- โปรแกรมจะจัดการเพิ่มบรรทัดในตารางให้ตามจำนวนข้อมูลใน Array อัตโนมัติ

## 🗺️ แผนการพัฒนา (Development Phases)

### Phase 1: ระบบแกนหลัก (Backend Core)
- ติดตั้งไลบรารี `docxtpl` และ `docxcompose` (สำหรับกรณีต้องการรวมไฟล์)
- สร้าง API Endpoint `/api/autogen` เพื่อรับไฟล์ `.docx` และ `.json`
- **Parameters ที่รองรับ:**
  - `output_format`: เลือกออกเป็น `docx` หรือ `pdf`
  - `split_files`: `true` (แยกไฟล์แล้วจับใส่ Zip) หรือ `false` (นำทุกรายการมาต่อกันเป็นไฟล์เดียว)
  - `filename_field` (Optional): ระบุชื่อคีย์ใน JSON เพื่อนำไปตั้งชื่อไฟล์ย่อย (เช่น "invoice_no")
  - `output_filename` (Optional): ตั้งชื่อไฟล์หลักที่ผู้ใช้จะดาวน์โหลด (ไฟล์ .zip หรือไฟล์รวม)
- เขียนลูปประมวลผล (Batch Processing) จัดการดึง Template มาเรนเดอร์แยกรายการ หรือ Merge รวมไฟล์ตามต้องการ
- สั่งเชื่อม LibreOffice เพื่อรองรับการ Output ออกเป็น PDF
- *สถานะ: เสร็จสมบูรณ์พร้อมใช้งาน 100%*
### Phase 2: ระบบหน้าบ้านพื้นฐาน (Frontend UI)
- สร้างเมนูใหม่ชื่อ **"สร้างเอกสารอัตโนมัติ (Auto-Gen)"**
- สร้าง Modal/Page สำหรับฟอร์มอัปโหลดไฟล์คู่ (Template + Data)
- สร้างตัวเลือก Output format: `.zip (DOCX)` หรือ `.zip (PDF)`
- ส่งข้อมูลไปหา API ใน Phase 1 และทำระบบรับไฟล์ดาวน์โหลดอัตโนมัติ
- *เป้าหมาย: ผู้ใช้สามารถใช้งานได้จริงแบบ End-to-End ผ่านหน้าเว็บ*

### Phase 3: การรองรับข้อมูลที่หลากหลาย (Data Parsers)
- เพิ่มการรองรับไฟล์ `.csv`, `.txt`, `.xlsx` (อ่านด้วย `csv.DictReader` และ `openpyxl`)
- สมมติฐานสำหรับไฟล์ตารางแบน (Flat file): 1 บรรทัด = 1 เอกสาร (ไม่มี Array ย่อยซ้อนกัน)
- เพิ่ม `csv_delimiter` (ตัวคั่นคอลัมน์) ฝั่ง UI ให้ผู้ใช้พิมพ์ปรับได้ (เช่น `,` หรือ `;` หรือ `	`)
- *สถานะ: เสร็จสมบูรณ์พร้อมใช้งาน 100%*
### Phase 4: ประสบการณ์ใช้งาน (UX Enhancement)
- ทำระบบ **"Preview Data"** ใน Frontend นำข้อมูล JSON/CSV/XLSX มาแสดงเป็นตารางให้ผู้ใช้เช็คก่อนกดสร้าง
- ทำ Loading Progress หรือสถานะแจ้งเตือน กรณีเอกสารมีจำนวนมากและใช้เวลานาน
- แสดงรูปแบบตัวแปร `{{ }}` กำกับที่หัวคอลัมน์ใน Preview เพื่อให้รู้ว่าใน Word ต้องพิมพ์อะไร
- *สถานะ: เสร็จสมบูรณ์พร้อมใช้งาน 100%*
